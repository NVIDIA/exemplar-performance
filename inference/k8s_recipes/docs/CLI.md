# `llmb-k8s` — CLI reference

`llmb-k8s` is used to execute Exemplar Performance inference benchmarking on Kubernetes.

______________________________________________________________________

## User Flow

There are four high level steps to execute a benchmark on a new cluster.

1. Create a cluster profile file for the benchmark job to leverage.

```bash
llmb-k8s init         --cluster <name>
```

2. Install prereqs and download model weights.

```bash
llmb-k8s install      --cluster <name>
```

3. Execute benchmark recipe (job).

```bash
llmb-k8s run          --recipe <path> --cluster <name>
```

4. Clean up results.

```bash
llmb-k8s publish      --recipe <path> --cluster <name> <run-dir>
```

### Usage Note

Users can specify details of their benchmarking job either with positional args or with named flags.

Positional:

```bash
llmb-k8s <verb> <cell-dir> <cluster-profile> [extra-args...]
```

Named flags:

```bash
llmb-k8s <verb> --recipe <cell-dir> --cluster <name> [extra-args...]
```

- A **cell-dir** is a recipe directory (`recipes/<scenario>/<distribution>/<name>/`, which contains
  `recipe.yaml`).
- A **cluster-profile** is the `<name>` of a `cluster-profiles/<name>.env` file. The profile supplies all cluster-specific
  variables.

## Verb reference

### Lifecycle (cell + profile)

| Verb        | Form                                                          | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dry-run`   | `<cell> <profile>`                                            | `dryrun.sh` — **OFFLINE** manifest validation: resolve every `${VAR}` + lint the rendered manifests **without touching the cluster**. Exit 0 = clean. (This is what `preflight` used to be.)                                                                                                                                                                                                                                                                                                                                                         |
| `preflight` | `<cell> <profile> [--wait-on-resources]`                      | `preflight.py` — the **LIVE, resource-aware** cluster check: namespace, free-GPU nodes (product + count, DRA-aware, taint-tolerated), PVCs, secrets, operators, RDMA/DCGM. **Hard-fails on an unreachable context.** Exit 0 = all hard checks pass (WARNs advisory), 1 = FAIL, 2 = usage/unreachable. `--wait-on-resources` polls the live free-GPU counts every 60s until a node fits, instead of failing when none does (Ctrl-C to stop waiting).                                                                                                  |
| `stage`     | `<cell> <profile>`                                            | Put the workload (dataset) on the PVC.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `deploy`    | `<cell> <profile>`                                            | `deploy.sh` — `kubectl apply` the server manifests (`rendered/*.yaml` except the bench Job). Idempotent.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `run`       | `<cell> <profile> [run-id] [flags]`                           | `run.sh` — the **full lifecycle** (preflight → namespace → stage → deploy → wait-ready → benchmark → fetch → **result** → teardown). The closing block prints the **verdict** — metric, value, the bar and tolerance, PASS/FAIL and the per-rung values — and writes `metrics_summary.csv` into the run dir, so you do not have to run the aggregator by hand to learn what the run measured. No bar configured → it says the run *cannot pass or fail, only report*; unevaluable → UNKNOWN naming the missing file, never silence. See flags below. |
| `analyze`   | `<cell> <results-dir>` (or `<cell> <profile> <results-dir>`)  | Aggregate metrics + exemplar check. **`analyze` reads a run DIRECTORY, not a cluster**, so the profile is optional: `llmb-k8s analyze <cell> results/<run-id>` is the natural form. A finished `run` now prints its own verdict, so this is mainly for re-scoring after the fact.                                                                                                                                                                                                                                                                    |
| `publish`   | `<cell> <profile> <results-dir> [--set-baseline] [--dry-run]` | `publish.py` — aggregate → metric → RESULTS.md data block → status bump → catalog rebuild. Dispatches by scenario.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `status`    | `<cell> <profile>`                                            | `observe.py` — one read-only panel: render freshness · published-hash drift · last run · live server Ready? · active Job. Read-only (no compat gate).                                                                                                                                                                                                                                                                                                                                                                                                |
| `logs`      | `<cell> <profile> [run-id] [--artifacts]`                     | `observe.py` — resolve the newest (or named) Job and stream its logs (Ctrl-C detaches; the Job keeps running). `--artifacts` instead prints the **post-TTL run record** from persisted `results/<run-id>` (run_meta per-rung pass/breach, wall time, publishable/fetch signals) — works after the Job is gone. Read-only.                                                                                                                                                                                                                            |

### `run` flags

Passed through `llmb-k8s run <cell> <profile> [run-id] <flags>` to `run.sh`:

| Flag                         | Effect                                                                                                                                                                            |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--managed-ns`               | Create the namespace if it does not exist.                                                                                                                                        |
| `--skip-stage`               | Skip staging (assume dataset already on the PVC).                                                                                                                                 |
| `--skip-server`              | Skip server deploy (reuse a running instance) — the resume path after a failure.                                                                                                  |
| `--no-load-gate`             | Opt out of MODEL-LOAD admission control. By default, runs that share a model-cache PVC load their weights ONE AT A TIME (then benchmark in parallel); this disables that.         |
| `--smoke-only`               | Run one concurrency rung only, **wall-capped** (env `SMOKE_WALL`, default 300s) — a quick path check, then stop (not a publishable result).                                       |
| `--teardown`                 | Scale the server to 0 after the sweep; with `--managed-ns` also deletes the namespace.                                                                                            |
| `--no-fetch`                 | Skip artifact extraction from the PVC.                                                                                                                                            |
| `--idle-guard[=MIN]`         | Background hang watchdog for the benchmark phase: if the server emits no new tokens for `MIN` min (default 30), cancel the run so it stops holding the GPU node.                  |
| `--rungs "N ..."`            | Override the concurrency list. Per-launch only; does **not** change the committed recipe.                                                                                         |
| `--crashloop-max-restarts K` | wait-ready fail-fast: abort if a server pod's `restartCount` reaches `K` (default 5; env `CRASHLOOP_MAX_RESTARTS`). Restart-based, so a slow legitimate cold load never trips it. |
| `--crashloop-window-min M`   | wait-ready fail-fast: abort if the server stays `CrashLoopBackOff` (0 ready) for `M` minutes (default 5; env `CRASHLOOP_WINDOW_MIN`).                                             |

`run.sh` prints the exact `publish` command + elapsed wall time on completion.

### Detached / disconnect-resilient flow

`run` waits locally for the whole lifecycle. If the laptop sleeps or SSH/Teleport drops, an already-applied
in-cluster Job may continue, but the local wait/fetch/cleanup path is interrupted; do not treat attached `run`
as disconnect-durable. The **detached** verbs decouple the launch from your session: `submit` fires-and-exits,
the Job runs to completion server-side, and `status`/`logs`/`collect` read the state it persisted — even
after the Job's TTL-GC. Same lane routing, same recipe truth; only the client lifetime changes.

| Verb              | Form                                                                      | Purpose                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `submit`          | `<cell> <profile> [run-id] [flags]`                                       | `submit.sh` — render + apply {a shared RWX control PVC + the bench Job (with `activeDeadlineSeconds` + short `ttlSecondsAfterFinished` + a wrapper streaming logs/`status.json`/`_submit.json` to the control PVC) + the server stack with an `ownerReference`→Job so GC cascade-deletes it}, write a local submit record, **print the run-id + status/logs/cancel/collect commands, and EXIT**. No local wait/fetch. |
| `cancel`          | `<run-id> [--cluster <profile>] [--dry-run \| --yes]`                     | Resolve the exact detached Job from the durable run record/index, fail closed unless its run-id and LLMB ownership labels match, then delete that one Job and wait for its owner-referenced server to terminate. Interactive confirmation by default; `--dry-run` lists exact targets; `--yes` is the headless form. Artifacts, logs/status, and the run-id index are retained for diagnosis.                         |
| `collect`         | `<run-id>` \| `--sweep <sweep-id>` `[--cluster <profile>] [publish-args]` | `resilient_status.py collect` — idempotent `fetch_results.sh` + local `publish.py` for a detached run (resolves run-id→cell from `_submit.json`/labels). `--sweep` collects **all** legs of a `--repeat` variance sweep, consolidates them into the original cell, and prints `compare --repro`.                                                                                                                      |
| `watch`           | `[run-id ...] [--interval N] [--once]`                                    | `watch_runs.py` — live **Gantt** timelines for all active parallel runs, refreshing every `N`s (default 15). Pass run-ids to watch only those. Read-only; Ctrl-C to exit.                                                                                                                                                                                                                                             |
| `status <run-id>` | `<run-id> [--cluster <profile>]`                                          | Detached form of `status`: a single positional that is **not** a cell dir reads the PVC `status.json` + Job `.status` `submit` left — survives Job TTL-GC and cold reconnect. (The `<cell> <profile>` panel form is unchanged.)                                                                                                                                                                                       |
| `logs <run-id>`   | `<run-id> [--cluster <profile>]`                                          | Detached form of `logs`: streams the PVC `runner.log` for a run-id, again surviving TTL-GC. (The `<cell> <profile> [run-id]` Job-log form is unchanged.)                                                                                                                                                                                                                                                              |

**`submit` flags** (beyond `run`'s `--rungs`/`--dry-run`, which it also accepts): `--deadline-seconds N`
(Job `activeDeadlineSeconds`), `--ttl-seconds N` (`ttlSecondsAfterFinished`, default 300),
`--health-timeout N` (server readiness budget). **Variance sweep:** `--repeat N` (alias `--variance N`)
launches `N` name-suffixed detached repeats that share one `benchmark_id` (so `collect --sweep` bands
them); `--stagger S` spaces the leg cold-starts (default 120s, guarding the shared model-cache); `--serial`
waits for each leg's Job instead of firing them in parallel. `submit --dry-run` runs fully **offline**
(shows the injected manifests / the sweep plan, applies nothing). No committed `recipe_hash` rolls — the
ownerRef/deadline/TTL/wrapper are injected over the already-rendered manifests at submit time.

### Cross-cell

| Verb      | Form                                                                                                                              | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `compare` | `<cell...>` · `--facet <scenario> <goal> <distribution>` · `--all` · `--runs <cell>` · `--repro <cell>` `[--baseline C] [--json]` | `analysis/compare.py` — comparison report. Cells/facet/`--all` compare *across cells* (hardware ranking or same-GPU reproducibility). **`--runs <cell>`** compares the **same cell across clusters** from its `runs.jsonl` ledger (cluster A versus cluster B): per-cluster value, spread, within-tolerance verdict, and a mixed-`recipe_hash` warning. **`--repro <cell>`** is the **within-cluster** counterpart — the same cell run N times on *one* cluster (the 3×-repeat band the fleet agents produce, which `--runs` collapses to 1/cluster). ### The fleet view (`watch -n 15 llmb-k8s fleet`)

`llmb-k8s fleet` (no cell-dir) is a **read-only, client-side, multi-cluster** status pane — a k9s-like
view, but across every cluster at once and non-interactive, so it composes with `watch`:

```bash
# active-runs-first snapshot: what's benchmarking, my GPUs, ETAs
llmb-k8s fleet
# LIVE view — defaults to the hierarchy pane (CLUSTER → CAPACITY →
llmb-k8s fleet --watch
                                   # NAMESPACE → INSTALLED/RUN·SERVER). Double-buffered (15s), never blanks.
# the older flat active-runs-first pane, live
llmb-k8s fleet --watch --flat
# OURS-only: skip cluster-scoped capacity reads → fast on every cluster
llmb-k8s fleet --fast
# expand each cluster's full job/server tree
llmb-k8s fleet --detail
# one cluster
llmb-k8s fleet --cluster cluster-a
# hide 0-GPU (CPU-only) active runs
llmb-k8s fleet --gpu-only
```

**`--watch` needs a terminal, and fits the frame to it.** Watch mode repaints on the *alternate screen
buffer*, which has **no scrollback** — so a frame taller than your terminal would scroll its own top away
with no trace. `--watch` therefore measures the live terminal each frame and **collapses by priority** when
the frame does not fit: spacing → build stamp → idle clusters → INSTALLED inventory → CAPACITY. The live
**RUN / SERVER rows, failures and the cluster/namespace bars they hang off are never what gets dropped**, and
every collapse is stated in place (`… N lines hidden (installed inventory)`) plus one footer
(`⚠ viewport: N of M lines hidden … — lengthen/widen the terminal, or run `fleet.sh` (no --watch) for the full render`). Nothing is ever dropped silently. **Piped** (stdout is not a TTY) `--watch` degrades to
exactly **one clean full render** and says so on stderr — a repainting watch stream into a file or a capture
buffer can only ever be truncated mid-table.
